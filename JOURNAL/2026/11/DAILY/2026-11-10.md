## Today's Focus: AWS IAM Policy and S3 Resource Scoping

## Scenario

An application needs to read its development configuration but must not modify files, delete files, or read production configuration.

The following bucket and object names are simulation examples; they do not need to exist.

| Operation                        | Example resource                       | Expected result   |
|----------------------------------|----------------------------------------|-------------------|
| Read development configuration   | `iam-practice-bucket/dev/config.json`  | Allow             |
| Update development configuration | `iam-practice-bucket/dev/config.json`  | Deny              |
| Delete development configuration | `iam-practice-bucket/dev/config.json`  | Deny              |
| Read production configuration    | `iam-practice-bucket/prod/config.json` | Deny              |

## 1. Write the Initial Policy

Save the following policy as `iam-readonly.json` (This JSON file is the input to the policy simulator. 
Saving it does not create or attach an IAM policy):

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ReadDevelopmentConfiguration",
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::iam-practice-bucket/dev/*"
    }
  ]
}
```

## 2. Test the Development Object

Run this command from the directory containing `iam-readonly.json`:

```bash
aws iam simulate-custom-policy \
  --profile management-admin \
  --policy-input-list file://iam-readonly.json \
  --action-names s3:GetObject s3:PutObject s3:DeleteObject \
  --resource-arns arn:aws:s3:::iam-practice-bucket/dev/config.json \
  --query 'EvaluationResults[].{Action:EvalActionName,Result:EvalDecision}' \
  --output table
```

Expected results:

| Action             | Expected decision  | Explanation                                               |
|--------------------|--------------------|-----------------------------------------------------------|
| `s3:GetObject`     | `allowed`          | Both the action and object ARN match the Allow statement  |
| `s3:PutObject`     | `implicitDeny`     | The supplied policy does not grant this action            |
| `s3:DeleteObject`  | `implicitDeny`     | The supplied policy does not grant this action            |

## 3. Test the Production Object

```bash
aws iam simulate-custom-policy \
  --profile management-admin \
  --policy-input-list file://iam-readonly.json \
  --action-names s3:GetObject \
  --resource-arns arn:aws:s3:::iam-practice-bucket/prod/config.json \
  --query 'EvaluationResults[].{Action:EvalActionName,Result:EvalDecision}' \
  --output table
```

Expected result: `implicitDeny`

## 4. Why Does Authorizing a Bucket ARN Not Authorize Its Objects?

Granting permission on a bucket ARN does not automatically grant permission on its objects.

S3 defines buckets and objects as separate IAM resource types.
This separation enables two useful access patterns:

- With `ListBucket` alone, a principal may list permitted object keys but cannot necessarily read their contents.
- With `GetObject` alone, a principal may download an authorized object when its key is known, without permission to list the bucket.

| Intended operation            | Action            | Required resource scope                            |
|-------------------------------|-------------------|----------------------------------------------------|
| List object keys              | `s3:ListBucket`   | `arn:aws:s3:::iam-practice-bucket`                 |
| Read one object's content     | `s3:GetObject`    | `arn:aws:s3:::iam-practice-bucket/dev/config.json` |
| Upload or overwrite an object | `s3:PutObject`    | `arn:aws:s3:::iam-practice-bucket/dev/config.json` |
| Delete an object              | `s3:DeleteObject` | `arn:aws:s3:::iam-practice-bucket/dev/config.json` |
