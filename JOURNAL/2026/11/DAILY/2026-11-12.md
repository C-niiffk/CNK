## Today's Focus: SNS Message Filtering with Two SQS Queues

## Background

Publish payment and alarm events to one SNS topic. Deliver payment events 
only to the payment queue and alarm events only to the alarm queue.

## 1. Create the Topic and Queues

Run 

```bash
mkdir -p sns-filter-practice
cd sns-filter-practice

export AWS_PROFILE=management-admin
export AWS_REGION=us-east-1
export AWS_PAGER=""

aws sso login --profile "$AWS_PROFILE"
aws sts get-caller-identity

LAB_ID="journal-$(python3 -c 'import uuid; print(uuid.uuid4().hex[:12])')"
TOPIC_ARN=$(aws sns create-topic --name "$LAB_ID" --query TopicArn --output text)

PAYMENT_URL=$(aws sqs create-queue --queue-name "$LAB_ID-payment" --query QueueUrl --output text)
ALARM_URL=$(aws sqs create-queue --queue-name "$LAB_ID-alarm" --query QueueUrl --output text)
```

## 2. Authorize Delivery and Configure Filters

Each queue needs a resource policy permitting this SNS topic to send messages:

```bash
for EVENT in payment alarm
do
  if [ "$EVENT" = payment ]; then
    QUEUE_URL="$PAYMENT_URL"
  else
    QUEUE_URL="$ALARM_URL"
  fi

  QUEUE_ARN=$(aws sqs get-queue-attributes \
    --queue-url "$QUEUE_URL" --attribute-names QueueArn \
    --query Attributes.QueueArn --output text)

  jq -n --arg queue "$QUEUE_ARN" --arg topic "$TOPIC_ARN" '{
    Version: "2012-10-17",
    Statement: [{
      Effect: "Allow",
      Principal: {Service: "sns.amazonaws.com"},
      Action: "sqs:SendMessage",
      Resource: $queue,
      Condition: {ArnEquals: {"aws:SourceArn": $topic}}
    }]
  }' > queue-policy.json

  jq -n --arg policy "$(cat queue-policy.json)" \
    '{Policy: $policy}' > queue-attributes.json

  aws sqs set-queue-attributes \
    --queue-url "$QUEUE_URL" \
    --attributes file://queue-attributes.json

  jq -n --arg event "$EVENT" '{
    FilterPolicyScope: "MessageBody",
    FilterPolicy: ({eventType: [$event]} | tojson),
    RawMessageDelivery: "true"
  }' > subscription-attributes.json

  aws sns subscribe \
    --topic-arn "$TOPIC_ARN" \
    --protocol sqs \
    --notification-endpoint "$QUEUE_ARN" \
    --attributes file://subscription-attributes.json
done
```

The resulting filters are `{"eventType":["payment"]}` and `{"eventType":["alarm"]}`.

## 3. Publish and Receive Events

Run

```bash
aws sns publish --topic-arn "$TOPIC_ARN" \
  --message '{"eventType":"payment","id":"P001"}'

aws sns publish --topic-arn "$TOPIC_ARN" \
  --message '{"eventType":"alarm","id":"A001"}'

aws sqs receive-message --queue-url "$PAYMENT_URL" \
  --wait-time-seconds 10 --max-number-of-messages 10 \
  --query 'Messages[].Body' --output json

aws sqs receive-message --queue-url "$ALARM_URL" \
  --wait-time-seconds 10 --max-number-of-messages 10 \
  --query 'Messages[].Body' --output json
```

Expected results

| Queue   | Event        |
|---------|--------------|
| Payment | payment/P001 |
| Alarm   | alarm/A001   |

## 4. Clean Up

Delete the SNS topic and both SQS queues:

```bash
aws sns delete-topic --topic-arn "$TOPIC_ARN"
aws sqs delete-queue --queue-url "$PAYMENT_URL"
aws sqs delete-queue --queue-url "$ALARM_URL"
```
