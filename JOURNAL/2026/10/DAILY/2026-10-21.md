## Today's Focus: JDK 8 to JDK 17 Upgrade - Platform and Application Changes

### Background

This journal documents the steps for upgrading the shared platform and the 
systems connected to it from JDK 8 to JDK 17, while ensuring that the 
upgraded platform continues to support systems running on JDK 8.

The platform team prepares a compatible framework, build environment, 
and runtime baseline. Application teams adapt their services and verify business behavior.

### Step 1 - Establish the Baseline and Upgrade Scope

**Platform team**

- Inventory the platform, shared framework, build tools and plugins, and 
components provided to applications, including Filebeat, SkyWalking Agent, and Nacos
- Define separate framework and dependency baselines for JDK 8 and JDK 17 
applications, ensuring both can integrate with the upgraded platform
- Identify supported deployment environments, including containers
and VMs
- Define the target dependency combinations and acceptance criteria

**Application teams**

- Identify affected code and integrations, and confirm the application's upgrade scope
- Capture baseline functional and performance results

### Step 2 - Prepare the JDK 17 Build Environment

**Platform team**

- Provide JDK 17 build images or installation packages
- Update CI runners and Maven plugins
- Configure the shared parent POM to use the intended Java compilation target
- Keep the previous build environment available for rollback

**Application teams**

- Configure the IDE project SDK and Maven runner
- Verify that local development and CI use the intended JDK
- Update the application parent POM or build configuration

```bash
java -version
mvn -version
```

### Step 3 - Upgrade Dependencies and Adapt Platform and Application Code

**Platform team**

- Upgrade the platform's own dependencies and shared framework 
components while maintaining a compatible framework release for JDK 8 applications
- Resolve dependency conflicts and verify that both application 
baselines can integrate with the upgraded platform
- Replace unsupported internal JDK API usage
- Update libraries that rely on restricted reflective access
- Publish versioned framework releases and upgrade notes

**Application teams**

- Adopt the framework release matching the application's JDK baseline
- Review direct and transitive dependencies
- Fix compilation errors caused by changed or removed APIs


```bash
mvn dependency:tree
```

### Step 4 - Update Runtime Images, Scripts, and Configuration

**Platform team**

- Provide a versioned JDK 17 runtime image or VM runtime package
- Verify compatibility with platform tools and shared components

**Application teams**

- Update the deployment image or Java executable path
- Add the following JVM options to the JDK 17 startup configuration 
to allow existing libraries to access non-public members through reflection:

```bash
--add-opens java.base/java.lang.reflect=ALL-UNNAMED
--add-opens java.base/java.lang=ALL-UNNAMED
```

### Step 5 - Perform Integration and Business Regression Testing

**Platform team**

Validate shared capabilities:

- Service registration and configuration retrieval
- Gateway routing and access control
- Database and messaging connectivity
- Logs, metrics, and distributed tracing
- Health probes and graceful shutdown

**Application teams**

Validate business behavior:

- API request and response formats
- Input validation and error handling
- Database transaction commits and rollbacks
- Authentication and authorization rules
- Encryption and decryption of existing data
- Response times and resource usage compared with the baseline

### Step 6 - Roll Out Gradually and Verify Rollback

**Platform team**

- Start with a representative pilot application
- Use a staged rollout appropriate to the deployment environment
- Define monitoring checkpoints and rollback triggers
- Preserve the previous runtime, framework artifacts, and deployment configuration

**Application teams**

- Deploy the validated application package
- Run smoke tests and monitor errors, latency, and business results
- Confirm successful integration with dependent systems
- Execute rollback if acceptance criteria are not met

### Responsibility Summary

| Area          | Platform team                                   | Application teams                            |
|---------------|-------------------------------------------------|----------------------------------------------|
| Compatibility | Define and validate the shared stack            | Validate application-specific dependencies   |
| Build         | Provide parent POM, plugins, and CI environment | Adopt the baseline and update local settings |
| Code          | Adapt shared framework components               | Adapt custom code and integrations           |
| Runtime       | Provide images, scripts, and agent guidance     | Update deployment configuration              |
| Testing       | Verify shared platform capabilities             | Verify business behavior and performance     |
| Rollout       | Provide rollout and rollback mechanisms         | Validate each application release            |
