## Today's Focus: Prometheus up Metric and Pod Health

## Category: Prometheus / OpenShift / Monitoring

### Background

Prometheus uses the `up` metric to determine whether a target 
can be successfully scraped. However, `up = 1` does not guarantee 
application health

### Observations

| Value            | Observation                                                                               |
|------------------|-------------------------------------------------------------------------------------------|
| `up = 1`         | Metrics scraping succeeds, but the application may still be unhealthy                     |
| `up = 0`         | Scraping fails, such as during a Pod failure or recovery                                  |
| No data (`null`) | Observed after manually deleting a Pod in OCP, when its target disappears from monitoring |

### Monitoring Improvement

1. Application Health Check

```bash
curl -f http://app:8080/actuator/health
```
Monitor the application health endpoint to detect application or dependency failures even when `up = 1`

2. Kubernetes Pod Health

Monitor Pod readiness and StatefulSet available replicas using `kube-state-metrics` to detect missing or unhealthy Pods
