# 2026-10-28

## Today's Focus: Nacos Database Migration from Derby to Oracle

## Category: Nacos / Database Migration

### Background

Nacos is deployed on OpenShift, using an embedded Derby database
with persistent storage (PVC). The migration involves moving data 
from Derby to Oracle and deploying a new Nacos version configured to connect to Oracle

### Migration Procedure

#### Step 1 - Backup and Stop Nacos

- Back up the Nacos PVC before migration
- Stop the existing Nacos application to prevent data changes
- Access the PVC and extract the `derby-data` directory

#### Step 2 - Export Derby Data

Five tables were found to contain data:

| Table           | Description                  |
|-----------------|------------------------------|
| config_info     | Configuration Data           |
| his_config_info | Configuration change history |
| roles           | User role assignments        |
| tenant_info     | Namespace information        |
| users           | User account information     |

Export data from four tables, excluding `his_config_info`, 
due to the complexity of historical data conversion. The exclusion 
does not affect Nacos configuration retrieval, as active configurations 
are stored in `config_info`

#### Step 3 - Import into Oracle

- Initialize the Oracle database by executing the Nacos SQL initialization script
- Convert the exported Derby data into Oracle-compatible SQL statements
- Import the data into the corresponding Oracle tables

#### Step 4 - Data Verification

Compare the data in Derby and Oracle:

- Record counts
- Configuration content and key fields
- User, role and namespace data

#### Step 5 - Deploy New Nacos Version

- Deploy the new Nacos version configured to connect to Oracle
- Verify Pod and cluster status
- Verify configuration retrieval, user authentication and namespace access
- Perform smoke tests

### Rollback Procedure

If the migration or deployment fails:

1. Stop the new Nacos version
2. Restore the PVC from the pre-migration backup
3. Redeploy the previous Nacos version configured to use Derby
4. Verify Nacos availability and configuration retrieval
5. Perform smoke tests
