# 2026-10-26

## Today's Focus: Rolling Upgrades for Nacos, Gateways and Applications

## Category: Nacos / Spring Cloud Gateway / Graceful Shutdown

### Background

Nacos, gateways and applications are upgraded to JDK 17 in stages to keep
services available during the upgrade

### Step 1 - Upgrade Nacos

Review relevant leader/follower roles, follow the supported restart order,
and maintain the required cluster quorum.

1. Remove the selected node from client-facing load-balancer rotation and
   confirm that clients can use healthy nodes
2. Stop the node, apply the runtime and release changes, and restart it
3. Verify cluster membership, configuration retrieval, and service discovery
4. Return the validated node to service before upgrading the next node

After all nodes are healthy, restore the intended Nacos load-balancer configuration

### Step 2 - Upgrade Gateway

1. Redirect new traffic to the remaining healthy gateway instances
2. Confirm that no new requests reach the selected gateway instance and allow in-flight requests to finish
3. Gracefully stop the gateway process
4. Update the runtime and release files, then restart the gateway
5. Verify Nacos connectivity, configuration loading, gateway routing and application health
6. Return the validated gateway to load-balancer rotation before upgrading the next instance


Health-check endpoints:

| Endpoint                   | Role                                                                     |
|----------------------------|--------------------------------------------------------------------------|
| /actuator/health/readiness | Report whether the instance is ready to receive traffic                  |
| /actuator/health           | Report overall application health based on configured health indicators  |

### Step 3 - Upgrade Application

1. Disable the selected instance for discovery-based traffic in Nacos
2. Confirm that callers have refreshed their instance lists and stopped sending it new requests
3. Wait for active requests to finish, including requests from 
callers that bypass service discovery, then gracefully stop the application process
4. Update the runtime and release files, then restart the application instance
5. Keep the instance out of normal traffic while checking Nacos connectivity, configuration retrieval,
   service registration, and application health
6. Run smoke tests against the upgraded instance before restoring normal traffic
7. Re-enable the validated instance in Nacos, then verify business 
requests through the gateway before upgrading the next instance

### Lessons Learned

- Rolling upgrades require sufficient remaining capacity and validation after each node or batch
- Safe rolling upgrades combine traffic withdrawal, request draining and graceful process shutdown
