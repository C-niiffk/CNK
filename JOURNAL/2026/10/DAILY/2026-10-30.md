# 2026-10-30

## Today's Focus: Should Nacos Be Retained After Moving to AWS?

## Category: AWS / Service Discovery

### Background

In management-platform, GRDC uses Nacos as the foundation for service
discovery and configuration. The design supports VM and Kubernetes applications across two sites.

### Separate the Requirements

Nacos may serve several purposes. Each capability needs its own assessment.

| Requirement           | AWS option to assess                               | Key consideration                                                     |
|-----------------------|----------------------------------------------------|-----------------------------------------------------------------------|
| Service discovery     | AWS Cloud Map or the runtime’s discovery mechanism | Registration, health information, client caching and instance updates |
| Dynamic configuration | AWS AppConfig                                      | Configuration delivery, validation, refresh and rollback              |

### Weigh the Trade-offs

| Area                       | Nacos as the GRDC foundation                                                                       | AWS alternatives                                                                                |
|----------------------------|----------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------|
| Application integration    | Reuses existing registration and configuration clients                                             | May require client or adapter changes and compatibility testing                                 |
| Site-aware behavior        | Provides the registry foundation for GRDC’s local registration, synchronization and fallback rules | Cloud Map provides discovery filters; equivalent policies still need integration and validation |
| Operational responsibility | Requires cluster maintenance, patching, monitoring and recovery                                    | Reduces some infrastructure work while introducing IAM, networking and service integration work |

The main reason to retain Nacos is preserving the existing application integration while developing GRDC’s site-aware behavior.

### Decision

The design retains Nacos as the GRDC foundation to limit application 
changes and reuse existing integration across deployment environments.
The decision can be revisited when an alternative meets the same requirements 
and offers a better balance of migration effort and ongoing operational cost.
